02 Crear el repositorio nuevo

  1. Extrae el ZIP. Abre la carpeta tarjeta-joven-salvador-alvarado.
  2. En GitHub → New repository, crea tarjeta-joven-salvador-alvarado. Puedes elegir visibilidad privada.
  3. Sube los archivos extraídos. package.json, app/, public/ y firebase.ts deben quedar en la raíz del repositorio.
  4. Incluye .env.example, que solo es una plantilla. Los archivos con valores reales, JSON de cuenta de servicio y contraseñas deben quedar fuera del repositorio.

Subir únicamente el ZIP a GitHub no permite que Vercel detecte la aplicación. Es necesario subir su contenido extraído.

03 Importar como un proyecto nuevo en Vercel

  1. Abre Vercel → Add New → Project y selecciona el repositorio nuevo.
  2. Confirma el nombre tarjeta-joven-salvador-alvarado y el equipo donde lo administrarás.
  3. Framework: Next.js. Root Directory: raíz (./). Node.js: 24.x. Install Command: npm ci. Build Command: npm run build. Output Directory: automático.
  4. Despliega primero sin credenciales. Por defecto funciona en presentación: portada y aviso, con registros y API cerrados.
  5. Guarda la URL que Vercel realmente asigne. Ese será el valor de APP_URL; no uses una URL de otro municipio.

No agregues Firebase todavía a Preview. Mantén los despliegues de revisión en presentación; al final conecta únicamente Production al Firebase nuevo.

04 Crear el Firebase de Salvador Alvarado

  1. En Firebase Console, crea un proyecto nuevo. Ejemplo de ID: tarjeta-joven-salvador-2026, sujeto a disponibilidad. Guarda el ID real. No elijas un proyecto anterior.
  2. Registra una aplicación web (</>). No necesitas activar Firebase Hosting porque la aplicación irá en Vercel. Guarda su configuración web.
  3. Activa Authentication → Sign-in method → Email/Password.
  4. En Authentication → Settings → Authorized domains, agrega el dominio de producción realmente asignado por Vercel, sin https:// ni rutas. Agrega después el dominio municipal cuando exista. localhost solo es necesario si vas a probar localmente.
  5. Crea Cloud Firestore, base predeterminada (default), modo producción. Elige la ubicación antes de crearla y registra cuál seleccionaste.
  6. Activa Storage en este mismo proyecto. Copia el nombre exacto del bucket. Para un proyecto nuevo normalmente termina en .firebasestorage.app.
Storage requiere Blaze. La documentación actual de Firebase exige vincular facturación para usar Cloud Storage. Existen cuotas sin cargo, pero no es una garantía de costo cero. Este programa usa Storage para fotos y documentos. Configura alertas de presupuesto; una alerta no impone un límite de gasto.

Publicar las reglas incluidas

  1. Abre firestore.rules del paquete y copia todo su contenido en Firestore → Rules. Publica dentro del proyecto nuevo.
  2. Haz lo mismo con storage.rules en Storage → Rules. Acepta la habilitación de acceso a Firestore si Firebase la solicita para evaluar roles.
  3. No copies estas reglas sobre los proyectos existentes.

Si prefieres usar Firebase CLI, ejecuta desde la carpeta nueva, sustituyendo ID_NUEVO_REAL:

firebase deploy --only firestore:rules,storage --project ID_NUEVO_REAL

Las reglas permiten operaciones según Master, Staff, negocio activo y titular. El SDK Admin actúa desde el servidor y no queda limitado por esas reglas; por eso las rutas también verifican identidad, rol y proyecto.

Obtener la cuenta de servicio

En Firebase → Project settings → Service accounts → Firebase Admin SDK → Generate new private key. Usa exclusivamente la cuenta del proyecto nuevo. Guarda sus valores privados en Vercel; no subas el JSON ni pegues la clave en el código o en el chat.

Guarda la clave privada y la contraseña de correo como Secret/sensible cuando la interfaz de Vercel lo permita. Las variables NEXT_PUBLIC_ son visibles en el navegador: nunca colocar contraseñas o claves privadas con ese prefijo.

Cambiar variables no actualiza una compilación existente. Después de guardarlas, ejecuta Redeploy. El control de configuración detendrá la compilación si activas el programa con datos faltantes o identificadores incompatibles.

  3. Agrega los campos siguientes, respetando el tipo y la mayúscula:

07 Probar el programa antes de difundirlo

Completa el domicilio, correo y aviso de privacidad con el instituto responsable antes de activar registros. Realiza las siguientes pruebas con cuentas y documentos de prueba propios del proyecto nuevo:

  1. Joven: solicitud → aparece como Pendiente → aprobación → correo → contraseña → acceso → QR personal.
  2. Menor de edad: se solicitan parentesco, credencial y aceptación de madre, padre o tutor. Confirmar borrado de documentos tras resolver la solicitud.
  3. Negocio: solicitud → aprobación → activación → publicación de beneficio → aparición en directorio y mapa.
  4. Canje: validar un QR nuevo, aplicar beneficio, verificar vigencia y restricciones, comprobar el comportamiento al repetir o deshacer un movimiento.
  5. Permisos: un joven no debe abrir registros ajenos; un negocio no debe administrar otros negocios; Staff no debe crear Master. Probar accesos directos a rutas y no solo botones.
  6. Correo: comprobar remitente, logos, links del proyecto nuevo y recuperación de contraseña.
  7. Móvil: revisar tamaños, navegación, cámara y QR en Android/iPhone, además de computadora.
  8. Aislamiento: las cuentas y QR anteriores no deben funcionar. Revisar que las pruebas solo aparezcan en el Firebase nuevo.

El paquete pasó compilación de producción, TypeScript y cuatro pruebas de aislamiento/activos. Las pruebas con navegador, Firebase y correo quedan pendientes hasta conectar los recursos nuevos. La base heredada no equivale a una auditoría integral de seguridad.

Tras probar, elimina los registros de prueba desde el proyecto nuevo, conserva el Master y publica únicamente promociones aprobadas. Confirma la apertura y difunde la URL nueva.

08 Si vas a trabajar desde Visual Studio Code

Usa una carpeta distinta. Instala Node.js 24 LTS y abre la terminal en la carpeta que contiene package.json:

npm ci
npm test
npm run typecheck
npm run build

Para conectarte en local, vincula explícitamente el proyecto Vercel nuevo y prepara .env.local a partir de .env.example. Usa un entorno de desarrollo propio si necesitas datos; no conectes desarrollo o Preview a la base de operación por costumbre.

vercel link --project tarjeta-joven-salvador-alvarado --scope TU_EQUIPO
npm run check:config
npm run dev

Los valores privados de Production pueden no descargarse mediante vercel env pull. Los de desarrollo deben configurarse aparte. Nunca copies la carpeta .vercel ni los archivos .env de Elota o Escuinapa.
